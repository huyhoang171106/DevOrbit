## 2. Kiến trúc & Dòng Dữ liệu (Architecture & Data Flow)

### 2.1. Kiến trúc WebSockets/STOMP

```
[Browser Client]
       │
       │ (WebSocket Connection /ws/community)
       ▼
[Spring Boot Backend]
  ├── WebSocketConfig
  │     └── ChannelInterceptor (Extract JWT from CONNECT header -> authenticate)
  ├── StudentCommunityController (Annotation @MessageMapping)
  └── SimpMessagingTemplate (Publish to /topic/channel/{channelId})
```

- ** Handshake & Authentication:**
  - Client gửi JWT trong header `Authorization` khi gửi khung `CONNECT`.
  - Một `ChannelInterceptor` kiểm tra header: `jwtService.isTokenValid(token)`. Nếu hợp lệ, gắn Authentication vào session của message. Nếu không, ngắt kết nối.
- **Luồng nhắn tin:**
  - Để gửi tin nhắn: Client gửi đến `/app/chat.send/{channelId}` với payload tin nhắn.
  - Backend xử lý, lưu vào Database thông qua `CommunityMessageRepository`, sau đó broadcast tin nhắn đến `/topic/channel/{channelId}`.
  - Client đăng ký nhận tin nhắn từ `/topic/channel/{channelId}` để cập nhật trực tiếp lên màn hình chat.

## 3. Thiết kế Cơ sở dữ liệu (Database Schema)

Tập tin migration `db/migration/V006__create_community_features.sql`:

```sql
-- 1. Phòng chat / Kênh chat
CREATE TABLE chat_channels (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    channel_id varchar(100) NOT NULL UNIQUE, -- VD: general, subject-se104, tech-react
    name varchar(255) NOT NULL,              -- VD: Kênh Chung, Nhập môn CNPM
    type varchar(50) NOT NULL,               -- GENERAL, COURSE, TECH_STACK
    reference_id varchar(50),                -- mamh của course hoặc id của tech_stack
    created_at timestamp with time zone DEFAULT now()
);

-- 2. Tin nhắn chat cộng đồng
CREATE TABLE community_messages (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    channel_id bigint NOT NULL REFERENCES chat_channels(id) ON DELETE CASCADE,
    student_id bigint NOT NULL REFERENCES student_users(id) ON DELETE CASCADE,
    content text NOT NULL,
    created_at timestamp with time zone DEFAULT now()
);

-- 3. Nhận xét / Đánh giá sao Repository
CREATE TABLE repo_reviews (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    repo_id bigint NOT NULL REFERENCES github_repos(id) ON DELETE CASCADE,
    student_id bigint NOT NULL REFERENCES student_users(id) ON DELETE CASCADE,
    rating integer NOT NULL CHECK (rating >= 1 AND rating <= 5),
    comment text,
    created_at timestamp with time zone DEFAULT now(),
    updated_at timestamp with time zone DEFAULT now(),
    CONSTRAINT uk_repo_student UNIQUE (repo_id, student_id)
);

-- 4. Upvote / Downvote Repository
CREATE TABLE repo_votes (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    repo_id bigint NOT NULL REFERENCES github_repos(id) ON DELETE CASCADE,
    student_id bigint NOT NULL REFERENCES student_users(id) ON DELETE CASCADE,
    vote_value integer NOT NULL CHECK (vote_value = 1 OR vote_value = -1),
    created_at timestamp with time zone DEFAULT now(),
    CONSTRAINT uk_repo_vote_student UNIQUE (repo_id, student_id)
);

-- 5. Nhận xét / Đánh giá sao Môn học
CREATE TABLE course_reviews (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    course_id bigint NOT NULL REFERENCES courses(stt) ON DELETE CASCADE,
    student_id bigint NOT NULL REFERENCES student_users(id) ON DELETE CASCADE,
    rating integer NOT NULL CHECK (rating >= 1 AND rating <= 5),
    comment text,
    created_at timestamp with time zone DEFAULT now(),
    updated_at timestamp with time zone DEFAULT now(),
    CONSTRAINT uk_course_student UNIQUE (course_id, student_id)
);

-- Indexes tối ưu hiệu năng
CREATE INDEX idx_comm_msgs_channel ON community_messages(channel_id);
CREATE INDEX idx_repo_reviews_repo ON repo_reviews(repo_id);
CREATE INDEX idx_course_reviews_course ON course_reviews(course_id);
```

## 4. Đặc tả API & WebSocket Contract

### 4.1. HTTP API (REST Endpoints)

- **Kênh Chat:**
  - `GET /api/student/community/channels` — Trả về danh sách tất cả các kênh (Chung, Môn học, Tech). Chỉ tự động hiển thị kênh môn học có trong dữ liệu hệ thống.
  - `GET /api/student/community/channels/{channelId}/messages?page=0&size=50` — Lấy lịch sử tin nhắn của một kênh (phân trang).
- **Social Repository:**
  - `POST /api/student/repos/{repoId}/vote` — Gửi vote (payload: `voteValue` = 1 hoặc -1 hoặc 0 để cancel vote).
  - `GET /api/repos/{repoId}/social-info` — Lấy tổng số vote score, số sao trung bình và danh sách reviews công khai (không cần đăng nhập).
  - `POST /api/student/repos/{repoId}/review` — Đăng hoặc cập nhật đánh giá (payload: `rating`, `comment`).
- **Social Course:**
  - `GET /api/courses/{courseId}/reviews` — Lấy danh sách reviews môn học và điểm đánh giá trung bình.
  - `POST /api/student/courses/{courseId}/review` — Đăng hoặc cập nhật đánh giá môn học (payload: `rating`, `comment`).

### 4.2. WebSocket/STOMP Destination Contract

- **Destination subscribe:** `/topic/channel/{channelId}`
- **Destination send message:** `/app/chat.send/{channelId}`
  - Payload gửi tin nhắn:
  ```json
  {
    "content": "Hello mọi người!"
  }
  ```
  - Payload nhận tin nhắn:
  ```json
  {
    "id": 1024,
    "channelId": 12,
    "studentId": 5,
    "senderName": "Nguyễn Văn A",
    "content": "Hello mọi người!",
    "createdAt": "2026-06-07T16:00:00Z"
  }
  ```

## 5. Chiến lược Phát triển Frontend UI/UX

1. **Thư viện kết nối:** Sử dụng `@stomp/stompjs` kết hợp với `sockjs-client` để tương thích tốt với Spring Boot WebSocket Message Broker.
2. **Giao diện Chat (`CommunityPage.tsx`):**
   - Thiết kế bento/glassmorphism tối giản kết hợp gam màu tối hiện đại.
   - Cột trái: Phân nhóm kênh `# Kênh chung`, `# Môn học`, `# Công nghệ`. Có thanh tìm kiếm nhanh kênh.

   - Cột phải: Danh sách thành viên đang hoạt động (tận dụng sự kiện WebSocket Session Connect/Disconnect hoặc cơ chế heartbeat đơn giản).
3. **Đánh giá trên CourseDetailPage & RepoDetailPage:**
   - Sử dụng Phosphor Icons hoặc Lucide để vẽ Rating Stars trực quan và tương tác.
   - Cho phép viết nhận xét dài định dạng markdown cơ bản hoặc văn bản thuần túy.
   - Tối ưu hóa UI: Ngay sau khi vote hoặc đánh giá thành công, cập nhật ngay lập tức giao diện (Optimistic UI Update) giúp trải nghiệm mượt mà.

## 6. Chiến lược Kiểm thử & Giảm thiểu Rủi ro

- **Rủi ro Kết nối WebSocket bị đứt:** Sử dụng tùy chọn tự động kết nối lại (`reconnectDelay: 5000`) của `@stomp/stompjs`.
- **Rủi ro SQL Injection / Spam tin nhắn:** Đặt cấu hình giới hạn kích thước ký tự tin nhắn gửi lên (VD: tối đa 1000 ký tự). Ở tầng Database, thực hiện validate đầu vào.
- **Kiểm thử thủ công (Manual Verification):**
  - Chạy backend và front-end, mở 2 cửa sổ ẩn danh khác nhau và đăng nhập bằng 2 tài khoản sinh viên UIT khác nhau.
  - Tham gia cùng 1 kênh chat, kiểm tra xem tin nhắn có gửi nhận tức thời thời gian thực hay không.
  - Thực hiện vote/review và F5 để đảm bảo điểm trung bình (average rating) được cập nhật chính xác.
